# CAPÍTULO 9: Sintaxis de Método, Manejo de Errores y Ecosistema

## La Puerta de Entrada al Ecosistema

En los capítulos anteriores aprendiste la gramática, los tipos de datos y los paradigmas fundamentales de Latino.NET. Sin embargo, un lenguaje de programación solo alcanza su verdadera madurez cuando se conecta con el mundo exterior: bases de datos, redes, compresión de archivos, cálculo científico, interfaces de usuario y el sistema operativo.

El **Capítulo 9** es el núcleo de esa potencia: un compendio exhaustivo que abarca la biblioteca estándar completa y el catálogo de plugins oficiales del lenguaje. Detrás de cada una de estas herramientas late la máquina virtual de **.NET 10**, ejecutando algoritmos críticos a la velocidad de código compilado de máquina.

### ¿Por Qué Esta Sección es Esencial?

Antes de sumergirte en las más de cincuenta bibliotecas que componen este ecosistema, necesitas conocer la **gramática común** que las gobierna. Esta sección preliminar no es un catálogo de funciones, sino el **marco arquitectónico unificado** que te enseñará a:

1. **Elegir el estilo de invocación adecuado:** Comprender cuándo usar sintaxis procedural (`cadena.recortar(s)`), cuándo aprovechar la invocación fluida por punto (`s.recortar()`) y cuándo encadenar transformaciones complejas con el operador Pipeline (`|>`).
2. **Dominar el sistema de tipos en tiempo de ejecución:** Reconocer qué estructuras admiten métodos encadenados y cuáles exigen llamadas funcionales debido a su diseño en memoria.
3. **Evitar trampas de sombreado (*shadowing*):** Resolver con total seguridad las colisiones de nombres entre claves de diccionarios y métodos de extensión.
4. **Construir patrones de software avanzados:** Implementar doble búfer con intercambio atómico (`~`), objetos nulos estructurales con fusión nula (`??`) y validaciones en cascada.
5. **Gobernar el manejo defensivo de excepciones:** Aplicar de forma idiomática los bloques `intentar/atrapar`, emitir errores de negocio con `lanzar()` y garantizar la integridad de datos mediante transacciones atómicas.

Dominar estas reglas desde el principio te permitirá leer, componer y depurar cualquier biblioteca del ecosistema con naturalidad y fluidez profesional.

> 💡 **Regla de Oro de la Biblioteca (Mantra de Latino.NET):**  
> *"Si existe una función nativa en la biblioteca o en un plugin, úsala."*  
> No reinventes la rueda escribiendo algoritmos pesados a mano en bucles interpretados. Cuando delegas la carga en los plugins de este capítulo, Latino.NET traslada el trabajo pesado directamente al compilador JIT de .NET 10.

## Sintaxis de Método (Invocación Fluida)

Las funciones de biblioteca en Latino.NET pueden ejecutarse a través de dos estilos complementarios:

### 1. Sintaxis Funcional Clásica (Procedural)

El dato se envía explícitamente como el primer argumento de la función de la librería:

```latino
texto  = "  Hola Mundo  "
limpio = cadena.recortar(texto)
mayus  = cadena.mayusculas(limpio)
```

### 2. Sintaxis de Método Fluida (Orientada a Objetos)

Las funciones de biblioteca compatibles se invocan directamente sobre el valor utilizando el operador de acceso por punto (`.`), como si fueran métodos de instancia:

```latino
resultado = "  Hola Mundo  ".recortar().mayusculas()
```

Ambas formas producen exactamente el mismo resultado y poseen el mismo rendimiento en tiempo de ejecución. La sintaxis de método elimina la acumulación de variables temporales y permite que las transformaciones se lean de forma lineal de izquierda a derecha.

## Tipos que Soportan Sintaxis de Método

El motor de Latino.NET (`Interpreter.cs`, `BindPrimitiveMethod`) implementa resolución dinámica de métodos de extensión exclusivamente sobre los siguientes tipos de datos:

| Tipo de Dato | Biblioteca Vinculada | Ejemplo de Método Fluido | Sintaxis Clásica Equivalente |
| :--- | :--- | :--- | :--- |
| **`cadena`** | `cadena` | `"hola".mayusculas()` | `cadena.mayusculas("hola")` |
| **`lista`** | `lista` | `[1, 2, 3].longitud()` | `lista.longitud([1, 2, 3])` |
| **`diccionario`** | `dic` | `d.llaves()` | `dic.llaves(d)` |

```latino
# Encadenamiento fluido en listas mutables:
numeros = [ 3, 1, 2 ]
numeros.agregar(4).ordenar().invertir()

escribir(numeros)  # Salida: [4, 3, 2, 1]
```

> ⚠️ **Restricción de Arquitectura:**  
> Las **tuplas**, los **conjuntos**, las **pilas**, las **colas**, los números (`decimal`) y los booleanos (`logico`) **NO** soportan sintaxis de método por punto en Latino.NET v1.0.81. Intentar hacer `(1, 2).longitud()` o `conj.union(otro)` arrojará un error de ejecución (`RuntimeError: El objeto de tipo '...' no tiene propiedades ni métodos`).  
> Para esas estructuras, debes invocar siempre la sintaxis funcional: `tupla.longitud(t)` o `conjunto.union(c1, c2)`. Para encadenar operaciones sobre números o tuplas, utiliza el operador Pipeline `|>`.

## Reglas de Precedencia en Diccionarios (Sombreado)

En los diccionarios existe una ambigüedad potencial: una clave almacenada puede llamarse exactamente igual que una función de la biblioteca `dic` (por ejemplo, `"longitud"` o `"valores"`).

Para resolver esto sin corromper tus datos, el despachador del motor aplica un **orden estricto de prioridades**:

1. **Instancias de Clases POO:** Tienen prioridad absoluta sobre sus propios campos y métodos.
2. **Claves del Diccionario:** Tienen prioridad sobre los métodos de `dic`. Si la clave existe en el diccionario, se devuelve su valor.
3. **Métodos de Extensión de `dic`:** Se resuelven únicamente si el diccionario **no** contiene una clave con ese nombre.

```latino
config = {"longitud": 50, "ancho": 100}

# Conflicto: 'longitud' existe como clave en el diccionario
escribir(config.longitud)       # Salida: 50 (lee el valor de la clave)

# Para invocar el método de conteo sin ambigüedades, usa la sintaxis funcional:
escribir(dic.longitud(config)) # Salida: 2 (cuenta los pares clave-valor)
```

## Orquestación: Sintaxis de Método vs. Operador Pipeline (`|>`)

La sintaxis de método y el operador Pipeline (`|>`) resuelven necesidades distintas en la arquitectura de un programa:

- **Usa Sintaxis de Método (`.`)** cuando encadenes transformaciones homogéneas que pertenezcan al **mismo tipo de dato** o biblioteca:

  ```latino
  urlLimpia = "  HTTPS://API.LATINO.NET/DATOS  ".recortar().minusculas()
  ```

- **Usa el Operador Pipeline (`|>`)** cuando el flujo de datos **atraviese diferentes bibliotecas**, involucre tipos heterogéneos o llame a funciones propias:

  ```latino
    # Cadena a lista de números pares a través de librerías distintas:
    numerosPares = " 3 7 10 22 5 "
        |> cadena.recortar                # cadena
        |> cadena.separar(" ")           # lista de cadenas
        |> lista.transformar(funcion(s) retornar anumero(s) fin)  # lista de números
        |> lista.filtrar(funcion(n) retornar n % 2 == 0 fin)      # lista filtrada

    escribir(numerosPares)  # [10, 22]
  ```

Ambas herramientas garantizan inmutabilidad y legibilidad de izquierda a derecha.

## Patrones Avanzados e Idiomáticos de Latino.NET

Latino.NET ofrece primitivas de lenguaje únicas que permiten implementar patrones de ingeniería de software con una concisión y elegancia superiores a las de otros entornos.

### 1. Patrón Doble Búfer con Swap Atómico (`~`)

En gráficos, simulaciones o videojuegos por consola, renderizar en pantalla mientras se calculan los datos produce parpadeos (*screen tearing*). Con el operador de intercambio atómico `~`, puedes alternar entre búferes de memoria sin variables temporales ni recarga en el recolector de basura:

```latino
# Configuración de Doble Búfer en listas de memoria
buferFrontal = [ "Frame A: Estado Inicial" ]
buferTrasero = [ "Frame B: Vacío" ]

funcion RenderizarSiguienteCuadro(nuevoEstado)
    # Dibujamos en el búfer trasero sin alterar la pantalla visible
    buferTrasero[0] = nuevoEstado
    
    # ¡Intercambio atómico en una sola instrucción!
    buferFrontal ~ buferTrasero
fin

RenderizarSiguienteCuadro("Frame B: Jugador se movió a (10, 20)")
escribir("Pantalla visible: " .. buferFrontal[0])
```

### 2. Patrón Objeto Nulo Estructural (Structural Null Object)

El operador de fusión nula `??` no se limita a valores escalares simples; puede respaldar estructuras de datos completas. Dado que en Latino.NET el operador `??` captura silenciosamente los errores de acceso a claves inexistentes en diccionarios, puedes garantizar un esquema completo por defecto en una sola expresión:

```latino
baseDatos = {
    "usr_1": {"nombre": "Ana", "rol": "administrador"}
}

# Esquema de respaldo completo (Fallback con comportamiento neutro):
usuarioInvitado = {
    "nombre": "Invitado",
    "rol": "lectura",
    "permisos": [ "ver_dashboard" ]
}

# Acceso seguro: si la clave no existe, ?? inyecta el diccionario invitado
usuario = baseDatos["usr_999"] ?? usuarioInvitado

# Todo el código posterior asume con total confianza que 'usuario' tiene forma completa:
escribir(ç("Bienvenido |usuario.nombre|, rol asignado: |usuario.rol|"))
```

### 3. Tuberías de Texto Concurrente de Alto Rendimiento (`texto` + `|>`)

Concatenar cadenas con `..` dentro de bucles pesados genera copias innecesarias en memoria. El plugin `texto` utiliza un constructor mutable thread-safe (`StringBuilder` encapsulado) cuyos métodos retornan el identificador del búfer, permitiendo tuberías fluidas de alta velocidad:

```latino
incluir("texto")

# Construcción de un reporte masivo con Pipeline:
bufferId = texto.crear(1024)
    |> texto.anexar("=== REPORTE EJECUTIVO ===\n")
    |> texto.anexar("Fecha: ", sis.tiempo(), "\n") # Salida variable (depende del momento de ejecución y hardware):
    |> texto.anexar("Estado del sistema: OPERATIVO\n")

reporteFinal = texto.obtener(bufferId)
texto.eliminar(bufferId)  # Liberación explícita de memoria

escribir(reporteFinal)
```

### 4. Micro-Framework de Pruebas Unitarias (TDD Nativo)

Aprovechando la igualdad estructural profunda de colecciones (`==`), la inspección dinámica con `tipo()` y las excepciones controladas con `lanzar()`, puedes implementar un motor de pruebas unitarias en español en menos de 20 líneas:

```latino
afirmar = {
    "iguales": funcion(esperado, obtenido, descripcion)
        si esperado != obtenido
            lanzar("FALLO: " .. descripcion .. " | Esperado: " .. esperado .. ", Obtenido: " .. obtenido)
        fin
        escribir("  ✅ PASÓ: " .. descripcion)
    fin,
    
    "cierto": funcion(condicion, descripcion)
        si no condicion
            lanzar("FALLO: La condición no se cumplió en: " .. descripcion)
        fin
        escribir("  ✅ PASÓ: " .. descripcion)
    fin
}

# --- Suite de Pruebas de Negocio ---
funcion CalcularDescuento(monto)
    retornar monto > 100 ? monto * 0.10 : 0
fin

escribir("Corriendo pruebas unitarias...")
intentar
    afirmar.iguales(15, CalcularDescuento(150), "Descuento del 10% en compras mayores a $100")
    afirmar.iguales(0, CalcularDescuento(50), "Sin descuento en compras menores a $100")
    afirmar.cierto(tipo(CalcularDescuento(200)) == "decimal", "El retorno debe ser numérico")
    escribir("\n🎉 ¡Todas las pruebas pasaron exitosamente!")
atrapar (error)
    escribir("\n🛑 " .. error)
fin
```

### 5. Tubería de Validación en Cascada (Validation Middleware)

El operador Pipeline `|>` no solo sirve para transformar datos matemáticos; también permite encadenar funciones de validación defensiva. Cada función actúa como un filtro puro: si el dato es válido lo devuelve intacto para el siguiente eslabón; si viola una regla, invoca `lanzar()` e interrumpe la tubería instantáneamente:

```latino
funcion ValidarNoVacio(txt)
    si cadena.esta_vacia(txt)
        lanzar("El campo no puede estar vacío.")
    fin
    retornar txt
fin

funcion ValidarLongitudMinima(txt)
    si cadena.longitud(txt) < 5
        lanzar("Debe contener al menos 5 caracteres.")
    fin
    retornar txt
fin

# Middleware en acción: recorta, valida presencia y verifica longitud
intentar
    usuarioValido = pedir("Nombre de usuario: ") # Entrada simulada: carlos_admin
        |> cadena.recortar
        |> ValidarNoVacio
        |> ValidarLongitudMinima

    escribir("✅ Usuario aceptado: " .. usuarioValido)
atrapar (error)
    escribir("❌ Validación rechazada: " .. error)
fin
```

## Manejo Robusto de Errores y Tipado en el Ecosistema

A partir de la versión 1.0, Latino.NET implementa validación estricta de tipos y aridad en todas las funciones nativas y plugins oficiales.

### Validación Automática de Argumentos

Si una función espera un tipo específico y recibe uno incompatible, el motor detiene la instrucción y arroja un `RuntimeError` en español antes de provocar una falla interna en .NET:

```latino
# ❌ Error de tipo controlado:
intentar
    lista.agregar(cierto, 10)
atrapar (e)
    escribir("Capturado: " .. e)
fin
# Salida: Capturado: [Línea 3] Se esperaba una lista, se recibió: LatinoBoolean
```

### El Bloque `intentar / atrapar (error) ... fin`

Es la estructura de defensa obligatoria ante operaciones que dependen del entorno externo:

1. **Entrada de Usuario:** `pedir()`, `leer()`.
2. **Sistema de Archivos:** `archivo.leer()`, `archivo.escribir()`.
3. **Peticiones de Red:** `web.obtener()`, `web.solicitar()`.
4. **Bases de Datos:** `sqlite.conectar()`, `sqlite.ejecutar()`.

```latino
incluir("sqlite")

intentar
    conexion = sqlite.conectar("datos_produccion.db")
    # Operaciones sobre la base de datos...
    sqlite.cerrar(conexion)
    archivo.borrar("datos_produccion.db")
atrapar (error)
    escribir("❌ Falla crítica de base de datos:")
    escribir("   Detalle: " .. error)
fin
```

> Sin `incluir("sqlite")` el bloque no falla visiblemente: el `intentar` captura el `Variable no definida: 'sqlite'` y lo muestra como si fuera un fallo de base de datos. Recuerda que los plugins se cargan con `incluir("nombre")` al inicio del archivo, y que una conexión abierta debe cerrarse siempre con `sqlite.cerrar()`.

### Lanzamiento de Errores de Negocio con `lanzar()`

Para abortar la ejecución ante violaciones de reglas de negocio y enviar un error estructurado a un bloque `atrapar`, utiliza la función global `lanzar()`:

```latino
funcion ProcesarTransferencia(saldo, monto)
    si monto <= 0
        lanzar("El monto a transferir debe ser mayor a cero.")
    fin
    
    si monto > saldo
        lanzar("Fondos insuficientes. Saldo actual: $" .. saldo)
    fin
    
    retornar saldo - monto
fin

intentar
    nuevoSaldo = ProcesarTransferencia(100, 500)
atrapar (error)
    escribir("Transacción rechazada: " .. error)
    # Salida: Transacción rechazada: [Línea 7] Fondos insuficientes. Saldo actual: $100
fin
```

### Unidad de Trabajo Transaccional con Guardas de Negocio

Al combinar la función nativa `sqlite.transaccion()` con el lanzamiento de excepciones de dominio mediante `lanzar()`, se obtiene el patrón de **Unidad de Trabajo** (*Unit of Work*) con reversión atómica (*rollback*) automática ante fallos de lógica de negocio:

```latino
# Esquema ilustrativo (patrón de diseño — no es un programa autónomo)
# Muestra la estructura de la función. Para ejecutarla necesitas:
#   1) una conexión 'db' abierta, con incluir("sqlite")
#   2) una tabla 'cuentas' con columnas (id, saldo)
# El ejemplo completo y ejecutable está en 9.17_plugin_sqlite.md
incluir("sqlite")

funcion TransferirFondos(db, cuentaOrigen, cuentaDestino, monto)
    intentar
        # sqlite.transaccion abre un bloque atómico en SQLite y le pasa el ID a la lambda
        sqlite.transaccion(db, funcion(idTx)
            # 1. Consultar saldo actual
            local filas = sqlite.consultar(idTx, "SELECT saldo FROM cuentas WHERE id = @id", {"id": cuentaOrigen})
            
            si lista.longitud(filas) == 0
                lanzar("La cuenta de origen no existe.")
            fin
            
            local saldoActual = filas[0]["saldo"]

            # 2. Guarda de Negocio: si viola la regla, lanzar() fuerza el Rollback inmediato
            si monto > saldoActual
                lanzar("Fondos insuficientes. Saldo disponible: $" .. saldoActual)
            fin

            # 3. Operaciones de débito y crédito atómicas
            sqlite.ejecutar(idTx, "UPDATE cuentas SET saldo = saldo - @monto WHERE id = @id", {
                "monto": monto,
                "id": cuentaOrigen
            })
            sqlite.ejecutar(idTx, "UPDATE cuentas SET saldo = saldo + @monto WHERE id = @id", {
                "monto": monto,
                "id": cuentaDestino
            })
        fin)
        
        escribir("✅ Transferencia bancaria procesada con éxito.")
    atrapar (error)
        # La transacción ya fue revertida automáticamente en la base de datos
        escribir("❌ Operación cancelada: " .. error)
    fin
fin
```

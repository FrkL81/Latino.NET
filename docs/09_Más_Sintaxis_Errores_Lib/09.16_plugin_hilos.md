## 9.16 Plugin hilos (Concurrencia Nativa)

El plugin `hilos` permite la ejecución asíncrona de funciones utilizando la *Task Parallel Library* (TPL) de .NET. Proporciona tres componentes integrados para crear subprocesos (`hilos`), sincronización de acceso a memoria compartida (`mutex`) y comunicación segura entre hilos (`canal`).

> **Requiere carga explícita:** `incluir("hilos")`

Cargar el plugin hace disponibles los tres plugins simultáneamente: `hilos`, `mutex` y `canal`.

### 🧵 Plugin `hilos` — Gestión de Subprocesos

Permite lanzar funciones en paralelo, consultar su estado y recuperar sus resultados.

| Función | Descripción | Retorna |
| :--- | :--- | :--- |
| `hilos.dormir(ms)` | Pausa la ejecución del hilo actual por N milisegundos. | `nulo` |
| `hilos.esperar(id, [ms])` | Bloquea el hilo actual hasta que el hilo `id` termine. Si se indica `ms`, espera como máximo esa cantidad de milisegundos; retorna `nulo` si se agota el tiempo. | Valor retornado por `f`, o `nulo` si hubo timeout |
| `hilos.esperarTodos(lista)` | Bloquea hasta que **todos** los hilos de la lista de IDs finalicen. Retorna los resultados en el mismo orden de la lista. | `lista` de resultados |
| `hilos.estaVivo(id)` | Consulta si el hilo `id` sigue en ejecución. No bloquea. | `logico` |
| `hilos.lanzar(f, [args...])` | Inicia la función `f` en un hilo separado. Los argumentos opcionales se pasan directamente a `f`. | `cadena` (ID único del hilo) |
| `hilos.limpiar()` | Elimina de la tabla interna todos los hilos que ya han finalizado. Útil en procesos de larga duración que lanzan muchos hilos para liberar memoria. | `numero` (cantidad de hilos eliminados) |

#### Aislamiento y Memoria

Cada hilo lanzado con `hilos.lanzar` recibe su **propio intérprete aislado**. Esto implica:

- La pila de recursión (`profundidad actual`) de cada hilo es independiente.
- Las variables locales y de ámbito no se comparten automáticamente entre hilos.
- Las librerías estándar (`mate`, `cadena`, `lista`, `sis`, etc.) están disponibles dentro de los hilos sin necesidad de volver a incluirlas.

Para **compartir datos entre hilos**, se deben pasar objetos por referencia como argumentos de `hilos.lanzar`. Los tipos que se pasan por referencia son:

| Tipo | ¿Compartido por referencia? | Nota |
| :--- | :--- | :--- |
| `lista` | ✅ Sí | Ambos hilos ven y modifican la misma lista |
| `diccionario` | ✅ Sí | Ambos hilos ven y modifican el mismo diccionario |
| `numero` | ❌ No | Se copia el valor; modificarlo en el hijo no afecta al padre |
| `cadena` | ❌ No | Inmutable por naturaleza |
| `logico` | ❌ No | Se copia el valor |

> **⚠️ Advertencia:** Modificar un `diccionario` o `lista` compartido sin protección (`mutex`) puede producir condiciones de carrera. Usa siempre `mutex.bloquear` al acceder a objetos compartidos desde múltiples hilos.

### 🧵 Plugin `mutex` — Sincronización de Acceso

Un **mutex** (abreviación de *mutual exclusion*) es un candado que garantiza que solo **un hilo a la vez** pueda ejecutar una sección crítica de código. Es indispensable cuando múltiples hilos modifican el mismo objeto compartido.

| Función | Descripción | Retorna |
| :--- | :--- | :--- |
| `mutex.bloquear(id)` | Intenta adquirir el candado. Si otro hilo ya lo tiene, **el hilo actual se detiene** en esta línea hasta que el candado quede libre. | `nulo` |
| `mutex.crear()` | Crea un nuevo mutex y retorna su identificador. | `cadena` (ID del mutex) |
| `mutex.eliminar(id)` | Elimina un mutex de la memoria. Lanza error si está bloqueado actualmente. | `logico` |
| `mutex.liberar(id)` | Libera el candado para que otro hilo pueda adquirirlo. **Solo el hilo que llamó `mutex.bloquear` puede llamar `mutex.liberar`.** | `nulo` |

#### Reglas de uso

- Siempre libera el mutex después de bloquearlo. Un mutex que nunca se libera bloquea permanentemente a los demás hilos que lo necesiten (deadlock).
- Usa `intentar / atrapar` para garantizar la liberación incluso si ocurre un error dentro de la región crítica.
- Intentar liberar un mutex que el hilo actual no posee produce un error de runtime.

```latino
incluir("hilos")
m = mutex.crear()

funcion tarea_segura(mtx, datos)
    mutex.bloquear(mtx)
    intentar
        # Región crítica: acceso exclusivo garantizado
        datos["total"] = datos["total"] + 1
    atrapar (err)
        escribir("Error inesperado: " .. err)
    fin
    mutex.liberar(mtx)
fin
```

> **⚠️ `mutex` requiere `incluir("hilos")`.** Sin esa línea, el motor responde `Variable no definida: 'mutex'`. El candado se crea pero la función todavía no se ha invocado; para completar el ciclo de vida, llámala y elimínalo al final:
>
> ```latino
> datos = { "total": 0 }
> tarea_segura(m, datos)
> escribir("Total protegido: " .. datos["total"])
> mutex.eliminar(m)
> ```

### 📨 Plugin `canal` — Comunicación entre Hilos

Un **canal** es un tubo de comunicación seguro entre hilos que sigue el modelo *FIFO* (primero en entrar, primero en salir). Permite al patrón *Productor–Consumidor*: un hilo envía datos y otro los recibe, sin necesidad de compartir memoria directamente.

| Función | Descripción | Retorna |
| :--- | :--- | :--- |
| `canal.cerrar(id)` | Marca el canal como cerrado. No se podrán enviar más mensajes. Los mensajes ya encolados pueden seguir recibiéndose. | `nulo` |
| `canal.crear()` | Crea un nuevo canal vacío y retorna su identificador. | `cadena` (ID del canal) |
| `canal.eliminar(id)` | Libera y remueve el canal de la memoria, liberando sus recursos. | `logico` |
| `canal.enviar(id, msg)` | Coloca el valor `msg` en el canal. Si el canal ya fue cerrado, produce un error. No bloquea. | `nulo` |
| `canal.recibir(id, [ms])` | Extrae el siguiente mensaje del canal. **Bloquea** si el canal está vacío hasta que llegue un mensaje. Si se indica `ms`, espera como máximo esa cantidad de milisegundos y retorna `nulo` si no llega nada. Si el canal está **cerrado y vacío**, retorna `nulo`. | El mensaje recibido, o `nulo` |

#### Comportamiento de `canal.recibir` según el estado del canal

| Estado del canal | ¿Hay mensajes? | Comportamiento |
| :--- | :--- | :--- |
| Abierto | Sí | Retorna el siguiente mensaje inmediatamente |
| Abierto | No | Bloquea hasta que llegue un mensaje (o hasta el timeout) |
| Cerrado | Sí | Retorna el siguiente mensaje (consume lo que queda) |
| Cerrado | No | Retorna `nulo` (señal de fin de datos) |

> **💡 Patrón recomendado:** El productor llama `canal.cerrar()` al terminar de enviar datos. El consumidor itera con `mientras dato != nulo`, lo que garantiza que procese todos los mensajes y termine limpiamente.

🎯 **Ejemplo 1: Hilo con Valor de Retorno**

Lanzar un hilo y recuperar el valor que retorna su función.

```latino
incluir("hilos")

funcion calcular(n)
    hilos.dormir(200)       # Simula trabajo de 200ms
    retornar n * n
fin

id = hilos.lanzar(calcular, 12)

escribir("Haciendo otras cosas mientras el hilo trabaja...")
resultado = hilos.esperar(id)   # Bloquea hasta obtener el resultado

escribir("Resultado: " .. resultado)  # → 144
```

🎯 **Ejemplo 2: Múltiples Hilos en Paralelo**

Lanzar varios hilos y esperar a que todos terminen con `hilos.esperarTodos`.

```latino
incluir("hilos")

funcion procesar(dato)
    hilos.dormir(100)
    retornar dato .. " procesado"
fin

entradas = ["alfa", "beta", "gamma", "delta"]
ids = [ ]

para item en entradas
    lista.agregar(ids, hilos.lanzar(procesar, item))
fin

resultados = hilos.esperarTodos(ids)

para r en resultados
    escribir(r)
fin
# → alfa procesado
# → beta procesado
# → gamma procesado
# → delta procesado
```

Un hilo produce datos y los envía por un canal. El hilo principal los consume hasta que el canal se cierra.

🎯 **Ejemplo 3: Patrón Productor–Consumidor con cierre y eliminación de canal**

```latino
incluir("hilos")

pipe = canal.crear()

funcion productor(c)
    desde (i = 1; i <= 5; i++)
        escribir("Productor: enviando " .. i)
        canal.enviar(c, i)
        hilos.dormir(100)
    fin
    canal.cerrar(c)     # Señaliza que no habrá más datos
fin

hilos.lanzar(productor, pipe)

# Consumidor en el hilo principal
escribir("Consumidor: esperando datos...")
dato = canal.recibir(pipe)

mientras dato != nulo
    escribir("Consumidor: recibido → " .. dato)
    dato = canal.recibir(pipe)
fin

escribir("✅ Todos los datos procesados.")
canal.eliminar(pipe)  # Higiene de recursos: destrucción del canal
```

**Salida esperada:**

```text
Consumidor: esperando datos...
Productor: enviando 1
Consumidor: recibido → 1
Productor: enviando 2
Consumidor: recibido → 2
...
✅ Todos los datos procesados.
```

🎯 **Ejemplo 4: Protección con Mutex**

Dos hilos incrementan un contador compartido. Sin mutex, el resultado sería impredecible. Con mutex, el resultado es siempre correcto.

```latino
incluir("hilos")

m = mutex.crear()
estado = {"contador": 0}    # Diccionario compartido por referencia

funcion incrementar(mtx, est)
    desde (i = 0; i < 50; i++)
        mutex.bloquear(mtx)
        est["contador"] = est["contador"] + 1
        mutex.liberar(mtx)
    fin
fin

h1 = hilos.lanzar(incrementar, m, estado)
h2 = hilos.lanzar(incrementar, m, estado)

hilos.esperar(h1)
hilos.esperar(h2)
mutex.eliminar(m)

escribir("Total: " .. estado["contador"])  # Siempre → 100
```

> **💡 ¿Por qué usar diccionario?** El `diccionario` se pasa por referencia: ambos hilos apuntan al mismo objeto en memoria. Una variable `numero` se copiaría, por lo que el hilo hijo modificaría su propia copia sin afectar al hilo principal.

Consumir mensajes con un tiempo límite de espera para evitar bloqueos indefinidos.

🎯 **Ejemplo 5: Recepción en canal con tiempo límite (Timeout) y liberación**

```latino
incluir("hilos")

c = canal.crear()

funcion productor_lento(ch)
    hilos.dormir(2000)          # Tarda 2 segundos
    canal.enviar(ch, "llegué")
fin

hilos.lanzar(productor_lento, c)

# Intentar recibir con timeout de 500ms
respuesta = canal.recibir(c, 500)

si respuesta == nulo
    escribir("⏱ Timeout: el productor tardó demasiado")
sino
    escribir("✅ Recibido: " .. respuesta)
fin

canal.eliminar(c)  # Higiene de recursos: destrucción del canal
```

### 🔧 Errores Comunes y Soluciones

| Error | Causa | Solución |
| :--- | :--- | :--- |
| Hilo bloqueado para siempre | `canal.recibir` esperando en un canal que nadie cerrará | Llama `canal.cerrar()` desde el productor al terminar, o usa timeout |
| `mutex.liberar` falla con error de propietario | Un hilo intentó liberar un mutex que no bloqueó | Asegúrate de que el mismo hilo que bloquea sea el que libera |
| Contador compartido da valor incorrecto | Variable `numero` pasada como argumento (se copia, no se comparte) | Usa un `diccionario` con el valor como clave: `{"v": 0}` |
| Deadlock (programa cuelga) | Dos hilos se esperan mutuamente para liberar su mutex | Diseña el orden de adquisición de mutex de forma consistente |
| Enviar a canal cerrado produce error | Se llamó `canal.enviar` después de `canal.cerrar` | Cierra el canal solo cuando el productor haya terminado de enviar |

🎯 **Ejemplo: Pruebas de humo rápidas de `hilos`**

```latino
incluir("hilos")

# Hilos
id = hilos.lanzar(funcion() escribir("hola") fin)
hilos.esperar(id)
hilos.esperar(id, 1000)
hilos.esperarTodos([id])
hilos.estaVivo(id)
hilos.limpiar()
hilos.dormir(100)

# Mutex
m = mutex.crear()
mutex.bloquear(m)
mutex.liberar(m)
mutex.eliminar(m)

# Canal
c = canal.crear()
canal.enviar(c, "msg")
canal.recibir(c, 100)
canal.cerrar(c)
canal.eliminar(c)
```

# Capítulo: 09_Más_Sintaxis_Errores_Lib

## 9.10 Librería `sis` (Sistema)

La librería `sis` permite interactuar con el entorno de ejecución, el hardware y el sistema operativo subyacente.

### ⚙️ Configuración y Estado

| Función | Parámetros | Descripción |
| :--- | :--- | :--- |
| `sis.apoyar()` | - | Muestra información para apoyar el proyecto y abre el enlace de patrocinio en el navegador. Retorna `cierto` si se abrió correctamente. |
| `sis.config(k, [v])` | `k, [v]` | Lee o escribe parámetros del runtime (ej: `max_stack`, `emoji_spacing` (0=desactivado, 2=recomendado para VS Code con xterm.js antiguo), `regex_timeout`). |
| `sis.cwd()` | - | Retorna el directorio de trabajo actual (Current Working Directory). |
| `sis.entorno(v, [d])` | `var, [def]` | Obtiene una variable de entorno. |
| `sis.manual()` | - | Abre el manual oficial PDF de Latino.NET. |
| `sis.operativo(q)` | `query` | Verifica si el SO actual coincide con el nombre dado (retorna booleano). |
| `sis.plataforma()` | - | Retorna un `diccionario` con información técnica completa del sistema. |
| `sis.usuario()` | - | Retorna el nombre del usuario que ejecuta el proceso. |

```latino
si sis.operativo("WIN")
    escribir("Ejecutando en Windows")
fin
```

### 🖥️ Información de la Plataforma

La función `sis.plataforma()` es la herramienta más completa para obtener detalles del entorno. Retorna un diccionario con las siguientes claves:

| Clave | Descripción | Ejemplo |
| :--- | :--- | :--- |
| `arquitectura` | Arquitectura del CPU | `"X64"`, `"Arm64"`, `"X86"` |
| `bits` | Bits del proceso | `64` o `32` |
| `directorio_home` | Ruta de la carpeta personal | `"/home/usuario"` o `"./usuario"` |
| `dotnet` | Versión del runtime .NET | `".NET 10.0.3"` |
| `memoria_proceso` | RAM usada por Latino (MB) | `25` |
| `procesadores` | Núcleos lógicos disponibles | `8` |
| `separador_rutas` | Carácter de separación de rutas | `"\"` o `"/"` |
| `so` | Nombre corto del SO | `"Windows"`, `"Linux"`, `"macOS"` |
| `usuario` | Nombre del usuario actual | `"juan.perez"` |
| `version` | Descripción completa del SO | `"Microsoft Windows 11..."` |

🎯 **Ejemplo: Construcción de rutas relativas portables entre plataformas**

```latino
info = sis.plataforma()
sep = info["separador_rutas"]
home = info["directorio_home"]

# Construir ruta válida en cualquier sistema
ruta_config = home .. sep .. ".mi_app" .. sep .. "config.json"
escribir("Guardando en: " .. ruta_config)
```

### ⏱️ Tiempo y Fecha

Para gestión avanzada de fechas, se recomienda usar el plugin `lapsos`.

| Función | Parámetros | Descripción |
| :--- | :--- | :--- |
| `sis.fecha(comp)` | `componente` | Obtiene partes: `seg`, `min`, `hora`, `dia`, `mes`, `anio`, `d_semana`, `d_año`. |
| `sis.milisegundos()` | - | Retorna un timestamp en milisegundos para medir rendimiento. |
| `sis.tiempo([fmt])` | `[formato]` | Retorna la fecha/hora actual como texto. Soporta formatos estilo C (`%Y-%m-%d`). |

### ⏸️ Control de Flujo

| Función | Parámetros | Descripción |
| :--- | :--- | :--- |
| `sis.argumentos()` | - | Retorna una `lista` con los argumentos pasados por línea de comandos. |
| `sis.dormir(n)` | `segundos` | Pausa el programa (suspensión del hilo). Acepta decimales (ej: `0.5`). |
| `sis.esperar(ms)` | `miliseg` | Pausa el programa por la cantidad de milisegundos indicada. |
| `sis.salir([codigo])` | `[codigo]` | Termina la ejecución del programa inmediatamente. Retorna el código numérico al sistema operativo (`0` por defecto). |

### 💻 Consola y Comandos

| Función | Parámetros | Descripción |
| :--- | :--- | :--- |
| `sis.ejecutar(cmd)` | `comando` | Ejecuta un comando en el shell del sistema y retorna su salida. |
| `sis.iraxy(x, y)` | `x, y` | Posiciona el cursor de la terminal en las coordenadas (columna, fila). |
| `sis.limpiar()` | - | Limpia el buffer de la terminal. |

🎯 **Ejemplo: Comando del Sistema**

```latino
# Listar archivos (multiplataforma)
comando = sis.operativo("WIN") ? "dir" : "ls"
salida = sis.ejecutar(comando)
escribir(salida)
```

> **⚠️ Importante:** `sis.ejecutar()` bloquea la ejecución de tu programa hasta que el comando del sistema operativo termina y devuelve su salida. No uses comandos interactivos que requieran que el usuario presione teclas en la terminal, ya que el programa se quedará congelado esperando eternamente.
>
> **💡 Consejo Pro (Ejecución en Segundo Plano):**
> Si necesitas ejecutar un comando pesado o lento sin bloquear tu programa principal, puedes combinarlo con el plugin oficial de concurrencia (`hilos`):
>
```latino
incluir("hilos")

# ⚠️ El comando DEBE terminar por sí solo, o el hilo quedará esperando para
# siempre. Un `ping` a un host remoto sin límite de paquetes es el error clásico:
# en Windows termina a los 4 paquetes, pero en Linux y macOS `ping` sin `-c` envía
# ICMP indefinidamente, y `hilos.esperarTodos()` se queda bloqueado para siempre.
# Por eso limitamos los paquetes según el sistema y usamos la loopback, que no
# depende de la red externa:
comandoPing = sis.operativo("WIN") ? "ping -n 2 127.0.0.1" : "ping -c 2 127.0.0.1"

# Lanzamos el comando pesado en un hilo secundario.
# hilos.lanzar() retorna un ID que después usaremos para recoger el resultado.
idHilo = hilos.lanzar(funcion()
    resultado = sis.ejecutar(comandoPing)
    retornar resultado
fin)

escribir("El programa principal sigue ejecutándose inmediatamente...")
# La interfaz o el flujo principal no se congela

# El patrón Fan-Out / Fan-In: esperamos al hilo y recogemos su valor de retorno.
resultados = hilos.esperarTodos([idHilo])
escribir("\n[Background] Ping completado:\n" .. resultados[0])
```

> ⚠️ **No olvides `hilos.esperarTodos()`.** `hilos.lanzar()` es *fire-and-forget*:
> si el programa principal termina antes de que el hilo acabe, **su salida se pierde**. Guarda el ID que devuelve `hilos.lanzar()` y pásalo a `hilos.esperarTodos([...])` para bloquear hasta que termine y recuperar su valor de retorno.

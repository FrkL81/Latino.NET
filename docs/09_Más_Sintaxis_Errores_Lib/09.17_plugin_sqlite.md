## 9.17 Plugin sqlite (Bases de Datos)

Imagina que tu programa puede recordar información para siempre, incluso después de cerrarse. Sin una base de datos, todo lo que tu programa calcula o recibe desaparece en el momento en que termina de ejecutarse. Con `sqlite`, puedes guardar datos en un archivo en tu computadora y volver a leerlos cuando quieras, aunque hayan pasado días, semanas o años.

**SQLite** es el motor de base de datos más usado del mundo. Lo utilizan aplicaciones como WhatsApp, Firefox, Android y millones de programas más. La razón es simple: no requiere instalar ningún servidor ni configuración compleja. Todo se guarda en un único archivo con extensión `.db` en tu carpeta.

> **Requiere carga explícita:** `incluir("sqlite")`

### 🧠 Conceptos Básicos (Para Principiantes)

Antes de ver las funciones, necesitas entender tres conceptos que se usan en todo el manual.

#### ¿Qué es una tabla?

Una base de datos organiza la información en **tablas**, que son como hojas de cálculo. Cada tabla tiene **columnas** (las categorías de información) y **filas** (los registros individuales).

```text
Tabla: usuarios
┌────┬──────────┬──────┬────────┐
│ id │ nombre   │ edad │ activo │
├────┼──────────┼──────┼────────┤
│  1 │ Frank    │  30  │   1    │
│  2 │ María    │  25  │   1    │
│  3 │ Roberto  │  42  │   0    │
└────┴──────────┴──────┴────────┘
```

#### ¿Qué es SQL?

**SQL** (*Structured Query Language*) es el lenguaje universal para hablar con bases de datos. Con él puedes crear tablas, insertar datos, buscarlos y modificarlos. Solo necesitas conocer cuatro comandos para el 90% de los casos:

| Comando SQL | ¿Qué hace? | Ejemplo |
| :--- | :--- | :--- |
| `CREATE TABLE` | Crea una tabla nueva | `CREATE TABLE productos (id INTEGER, nombre TEXT)` |
| `DELETE` | Elimina filas | `DELETE FROM productos WHERE id = 1` |
| `INSERT INTO` | Agrega una fila nueva | `INSERT INTO productos VALUES (1, 'Manzana')` |
| `SELECT` | Lee filas existentes | `SELECT * FROM productos` |
| `UPDATE` | Modifica filas existentes | `UPDATE productos SET nombre = 'Pera' WHERE id = 1` |

#### ¿Qué es una conexión?

Para usar una base de datos, primero debes "conectarte" a ella, igual que abres un archivo antes de leerlo. `sqlite.conectar()` abre esa conexión y te da un **ID** (una cadena única) que usarás en todas las demás operaciones. Cuando termines, debes cerrar la conexión con `sqlite.cerrar()`.

### 📋 Referencia de Funciones

| Función | Descripción | Retorna |
| :--- | :--- | :--- |
| `sqlite.cerrar(id)` | Cierra la conexión y libera el archivo. | `logico` |
| `sqlite.conectar(ruta)` | Abre o crea una base de datos SQLite. Acepta una ruta de archivo o `":memory:"` para bases de datos volátiles en memoria RAM. | `cadena` (ID) |
| `sqlite.consultar(id, sql, [params])` | Ejecuta un `SELECT` y retorna los resultados. | `lista` de `dic` |
| `sqlite.ejecutar(id, sql, [params])` | Ejecuta una instrucción que no retorna datos. **Requiere prefijo `@` en los parámetros.** | `numero` |
| `sqlite.transaccion(id, funcion)` | Ejecuta una función dentro de una transacción con rollback automático. | valor de función |
| `sqlite.ultimo_id(id)` | Retorna el ID autogenerado del último `INSERT`. | `numero` |

El flujo básico siempre es el mismo: conectar → crear tabla → insertar → consultar → cerrar.

🎯 **Ejemplo: Ciclo de vida básico en SQLite con limpieza de disco**

```latino
incluir("sqlite")

# 1. Conectar (crea el archivo si no existe)
db = sqlite.conectar("mi_primera_db.db")
escribir("Conectado. ID: " .. db)

# 2. Crear la tabla (solo la primera vez que corres el programa)
sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS personas (
    id      INTEGER PRIMARY KEY,
    nombre  TEXT,
    edad    INTEGER
)")

# 3. Insertar datos
sqlite.ejecutar(db, "INSERT INTO personas (nombre, edad) VALUES ('Ana', 28)")
sqlite.ejecutar(db, "INSERT INTO personas (nombre, edad) VALUES ('Luis', 35)")

# 4. Consultar y mostrar
personas = sqlite.consultar(db, "SELECT * FROM personas")

escribir("\n--- LISTA DE PERSONAS ---")
para p en personas
    # Puedes acceder directamente a p["id"]
    # Usamos escribirf para alinear el texto de forma limpia
    escribirf("[ID: {0}] {1} tiene {2} años.\n", p["id"], p["nombre"], p["edad"])
fin

# 5. Cerrar y eliminar archivo de prueba
sqlite.cerrar(db)
archivo.borrar("mi_primera_db.db")
```

**Salida:**

```text
Conectado. ID: 275e2e3f-4cac-476b-a8e7-a8d307abf2fd

--- LISTA DE PERSONAS ---
[ID: 1] Ana tiene 28 años.
[ID: 2] Luis tiene 35 años.
```

> **💡 Nota:** `CREATE TABLE IF NOT EXISTS` es una buena práctica. Si la tabla ya existe, SQLite la ignora en lugar de lanzar un error. Así puedes correr el mismo script muchas veces sin problemas.
>
> **🧹 Limpieza del archivo temporal:** Después de cerrar la conexión, el archivo físico sigue existiendo en disco. Si el ejemplo es una prueba o demostración, elimina el archivo para no contaminar tu entorno de trabajo:
>
> ```latino
> archivo.borrar("mi_primera_db.db")
> ```

### 🛡️ Protección contra Inyección SQL (Parámetros)

Nunca construyas una consulta SQL pegando texto del usuario directamente. Esto se llama **Inyección SQL** y es el ataque más común en aplicaciones con bases de datos.

```latino
# Fragmento ilustrativo: asume que 'db' es una conexión válida (ver Ejemplo 1)
# ❌ PELIGROSO: No hagas esto nunca
nombre_usuario = "Frank' OR '1'='1"
sqlite.consultar(db, "SELECT * FROM usuarios WHERE nombre = '" .. nombre_usuario .. "'")
# El atacante puede manipular la consulta y leer TODA la base de datos

# ✅ SEGURO: Usa parámetros con @nombre
sqlite.consultar(db, "SELECT * FROM usuarios WHERE nombre = @nom", {"@nom": nombre_usuario})
# El motor trata el valor como texto puro, nunca como código SQL
```

El motor acepta el símbolo `@` en los nombres de parámetros, **con o sin él en el diccionario**:

```latino
incluir("sqlite")
db = sqlite.conectar("tienda.db")

sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS productos (
    id      INTEGER PRIMARY KEY,
    nombre  TEXT    NOT NULL,
    precio  REAL,
    stock   INTEGER DEFAULT 0
)")

# Estilo RECOMENDADO: el @ explícito en el diccionario
# Hace visible de un vistazo qué claves se enlazan con el SQL
sqlite.ejecutar(db, "INSERT INTO productos (nombre, precio, stock) VALUES (@nom, @precio, @stock)", {
    "@nom":    "Manzana Roja",
    "@precio": 1.50,
    "@stock":  100
})

# Estilo ACEPTADO (más corto): el motor añade el @ que falta
sqlite.ejecutar(db, "INSERT INTO productos (nombre, precio, stock) VALUES (@nom, @precio, @stock)", {
    "nom":    "Pera Verde",
    "precio": 2.25,
    "stock":  75
})
# Estilo CLÁSICO: los parámetros llevan su @ explícito (otro producto)
sqlite.ejecutar(db, "INSERT INTO productos (nombre, precio, stock) VALUES (@nom, @precio, @stock)", {
    "@nom":    "Uva Morada",
    "@precio": 3.50,
    "@stock":  40
})

# Consulta con filtro parametrizado
caros = sqlite.consultar(db, "SELECT * FROM productos WHERE precio > @min", {"@min": 1.80})

para p en caros
    escribir(p["nombre"] .. " → $" .. p["precio"])
fin

sqlite.cerrar(db)
archivo.borrar("tienda.db")
```

### ⚡ Transacciones

Una **transacción** es un grupo de operaciones que se ejecutan como una sola unidad. O todas tienen éxito, o ninguna se guarda. Esto tiene dos ventajas:

1. **Velocidad:** Insertar 1000 filas dentro de una transacción es hasta 100 veces más rápido que hacerlo una por una, porque SQLite solo escribe en el disco una vez al final.
2. **Seguridad:** Si ocurre un error a mitad del proceso, la transacción se cancela (*rollback*) y la base de datos queda exactamente como estaba antes.

```latino
incluir("sqlite")
db = sqlite.conectar("inventario.db")

sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS movimientos (
    id        INTEGER PRIMARY KEY,
    producto  TEXT,
    cantidad  INTEGER,
    tipo      TEXT
)")

# Insertar 500 movimientos dentro de una transacción
sqlite.transaccion(db, funcion(conn)
    desde (i = 1; i <= 500; i++)
        tipo = i % 2 == 0 ? "entrada" : "salida"
        sqlite.ejecutar(conn, "INSERT INTO movimientos (producto, cantidad, tipo) VALUES (@p, @c, @t)", {
            "@p": "Producto-" .. acadena(i),
            "@c": i * 10,
            "@t": tipo
        })
    fin
    retornar "ok"
fin)

total = sqlite.consultar(db, "SELECT COUNT(*) AS total FROM movimientos")
escribir("Movimientos guardados: " .. total[0]["total"])

sqlite.cerrar(db)
archivo.borrar("inventario.db")
```

**¿Qué pasa si hay un error dentro de la transacción?**

```latino
incluir("sqlite")

db = sqlite.conectar("transaccion.db")
sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS movimientos (id INTEGER PRIMARY KEY, producto TEXT)")

intentar
    sqlite.transaccion(db, funcion(conn)
        sqlite.ejecutar(conn, "INSERT INTO movimientos (producto) VALUES (@p)", {"@p": "OK"})
        sqlite.ejecutar(conn, "ESTO NO ES SQL VÁLIDO")   # Error aquí
        sqlite.ejecutar(conn, "INSERT INTO movimientos (producto) VALUES (@p)", {"@p": "Nunca llego"})
    fin)
atrapar (err)
    escribir("Error capturado: " .. err)
    escribir("La base de datos quedó intacta (rollback automático)")
fin

# Comprobamos que el rollback fue REAL: la tabla debe seguir vacía
filas = sqlite.consultar(db, "SELECT COUNT(*) AS total FROM movimientos")
escribir("Filas tras el rollback: " .. filas[0]["total"])

sqlite.cerrar(db)
archivo.borrar("transaccion.db")
```

**Salida verificada** (ejecutado con `latino rollback.lat`):

```text
Error capturado: [Línea 9] Error SQL: SQLite Error 1: 'near "ESTO": syntax error'.
La base de datos quedó intacta (rollback automático)
Filas tras el rollback: 0
```

Observa lo que demuestra ese `0`: la primera inserción (`"OK"`) **sí llegó a ejecutarse**, pero al fallar la segunda sentencia SQLite deshizo *todas* las operaciones de la transacción. Eso es el *rollback*: no es que la sentencia inválida se ignore, sino que la unidad completa se revierte.

> 💡 **El rollback y la propagación son dos cosas distintas.** `sqlite.transaccion` primero revierte los cambios y después **relanza** el error, de modo que el `intentar ... atrapar` exterior sí lo recibe (como se ve en la salida: capturó el error de SQL de la línea 9). El orden es: se deshace la unidad de trabajo, y luego el error sube hasta tu manejador. Por eso el ejemplo puede tanto afirmar que hubo rollback como imprimir el mensaje de error.

### 🔑 Obtener ID del Registro Insertado (`sqlite.ultimo_id`)

Cuando insertas un registro con `PRIMARY KEY` automático, normalmente necesitas saber qué ID le asignó SQLite para enlazarlo con otros datos.

```latino
incluir("sqlite")
db = sqlite.conectar("blog.db")

sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS articulos (id INTEGER PRIMARY KEY, titulo TEXT)")

sql = "CREATE TABLE IF NOT EXISTS comentarios ("
    .. "id INTEGER PRIMARY KEY, "
    .. "articulo_id INTEGER, "
    .. "texto TEXT)"

sqlite.ejecutar(db, sql)

sqlite.transaccion(db, funcion(conn)
    # Insertar artículo
    sqlite.ejecutar(conn, "INSERT INTO articulos (titulo) VALUES (@t)", {"@t": "Mi primer artículo"})
    id_articulo = sqlite.ultimo_id(conn)
    escribir("Artículo creado con ID: " .. id_articulo)

    # Insertar comentarios vinculados al artículo recién creado
    sqlite.ejecutar(conn, "INSERT INTO comentarios (articulo_id, texto) VALUES (@aid, @txt)", {
            "@aid": id_articulo,
            "@txt": "¡Excelente artículo!"
        })
    sqlite.ejecutar(conn, "INSERT INTO comentarios (articulo_id, texto) VALUES (@aid, @txt)", {
            "@aid": id_articulo,
            "@txt": "Muy útil, gracias."
        })
fin)

# Consulta con JOIN para leer artículo y sus comentarios
resultados = sqlite.consultar(db, "
    SELECT a.titulo, c.texto
    FROM articulos a
    JOIN comentarios c ON a.id = c.articulo_id
    WHERE a.id = @id
", {"@id": 1})

para r en resultados
    escribir("[" .. r["titulo"] .. "] → " .. r["texto"])
fin

sqlite.cerrar(db)
archivo.borrar("blog.db")
```

### 🗂️ Operaciones CRUD Completas

Este ejemplo muestra el ciclo de vida completo de un registro.

```latino
incluir("sqlite")
db = sqlite.conectar("contactos.db")

sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS contactos (
    id       INTEGER PRIMARY KEY,
    nombre   TEXT NOT NULL,
    telefono TEXT,
    activo   INTEGER DEFAULT 1
)")

# CREATE: Insertar
sqlite.ejecutar(db, "INSERT INTO contactos (nombre, telefono) VALUES (@n, @t)", {
    "@n": "Carlos Pérez",
    "@t": "555-1234"
})
id_carlos = sqlite.ultimo_id(db)
escribir("Contacto creado con ID: " .. id_carlos)

# READ: Consultar uno
resultado = sqlite.consultar(db, "SELECT * FROM contactos WHERE id = @id", {"@id": id_carlos})
contacto = resultado[0]
escribir("Nombre: " .. contacto["nombre"] .. " | Tel: " .. contacto["telefono"])

# UPDATE: Modificar
filas = sqlite.ejecutar(db, "UPDATE contactos SET telefono = @t WHERE id = @id", {
    "@t":  "555-9999",
    "@id": id_carlos
})
escribir("Filas actualizadas: " .. filas)

# DELETE: Eliminar (borrado lógico, mejor práctica)
sqlite.ejecutar(db, "UPDATE contactos SET activo = 0 WHERE id = @id", {"@id": id_carlos})

# Consultar solo activos
activos = sqlite.consultar(db, "SELECT * FROM contactos WHERE activo = 1")
escribir("Contactos activos: " .. lista.longitud(activos))

sqlite.cerrar(db)
archivo.borrar("contactos.db")
```

### 📐 Tipos de Datos en SQLite

SQLite maneja tipos de datos de forma diferente a otros sistemas. El plugin hace la conversión automáticamente:

| Tipo en SQLite | Tipo en Latino | Notas |
| :--- | :--- | :--- |
| `BLOB` | `cadena` | Datos binarios (no recomendado desde Latino) |
| `INTEGER` | `numero` | Números enteros |
| `NULL` | `nulo` | Valor vacío o no definido |
| `REAL` | `numero` | Números decimales |
| `TEXT` | `cadena` | Texto de cualquier longitud |

**Booleanos:** SQLite no tiene tipo booleano nativo. La librería convierte automáticamente:

- `verdadero` → se guarda como `1`
- `falso` → se guarda como `0`
- Al leer, recibirás `1` o `0` (número), no `verdadero`/`falso`

```latino
incluir("sqlite")

db = sqlite.conectar("booleanos.db")
sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS usuarios (id INTEGER PRIMARY KEY, activo INTEGER)")
sqlite.ejecutar(db, "INSERT INTO usuarios (activo) VALUES (@a)", {"@a": verdadero})

# Leer y convertir manualmente (SQLite guarda los booleanos como 1/0)
u = sqlite.consultar(db, "SELECT activo FROM usuarios WHERE id = 1")[0]
esta_activo = u["activo"] == 1   # Convertir 1/0 a verdadero/falso

sqlite.cerrar(db)
archivo.borrar("booleanos.db")
```

### 🔧 Errores Comunes y Soluciones

| Error | Causa | Solución |
| :--- | :--- | :--- |
| Archivo `.db` no se borra | La conexión sigue abierta | Llama `sqlite.cerrar(db)` antes de intentar borrar el archivo |
| Base de datos bloqueada | Dos conexiones escribiendo al mismo tiempo | Usa una sola conexión por archivo, o implementa un mutex |
| `Conexión inválida` | Se usó un ID de conexión cerrada o inválida | Verifica que el `db` retornado por `conectar` sea el que pasas a las demás funciones |
| `Error SQL: NOT NULL constraint failed` | Insertar sin un campo obligatorio | Incluye todos los campos marcados como `NOT NULL` |
| `Error SQL: no such table` | Consultar una tabla que no existe | Verifica que creaste la tabla antes de consultarla |
| `Error SQL: table already exists` | Crear una tabla que ya existe | Usa `CREATE TABLE IF NOT EXISTS` |

### 📋 Referencia Rápida

```latino
incluir("sqlite")

# — Conexión (se cierra AL FINAL, después de todo el trabajo) —
db = sqlite.conectar("mi_app.db")   # Abrir/crear base de datos

# — Estructura —
sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS tabla (
    id     INTEGER PRIMARY KEY,
    nombre TEXT,
    valor  REAL
)")

# — Escritura —
sqlite.ejecutar(db, "INSERT INTO tabla (nombre, valor) VALUES (@n, @v)", {"@n": "dato", "@v": 3.14})
id = sqlite.ultimo_id(db)

sqlite.ejecutar(db, "UPDATE tabla SET valor = @v WHERE id = @id", {"@v": 9.99, "@id": id})

# — Lectura (antes de borrar: la tabla debe tener filas para leer [0]) —
filas = sqlite.consultar(db, "SELECT * FROM tabla")
una   = filas[0]          # Primera fila
campo = una["nombre"]     # Acceder a columna por nombre

# — Borrado —
sqlite.ejecutar(db, "DELETE FROM tabla WHERE id = @id", {"@id": id})

# — Transacción —
sqlite.transaccion(db, funcion(conn)
    desde (i = 1; i <= 1000; i++)
        sqlite.ejecutar(conn, "INSERT INTO tabla (nombre) VALUES (@n)", {"@n": "item-" .. i})
    fin
fin)

# — Cierre e higiene (siempre al final) —
sqlite.cerrar(db)                    # Liberar el archivo
archivo.borrar("mi_app.db")          # Eliminar archivo de prueba (si aplica)
```

🎯 **Ejemplo: Pruebas de Humo Rápidas**

```latino
incluir("sqlite")

db = sqlite.conectar("test.db")
sqlite.ejecutar(db, "CREATE TABLE IF NOT EXISTS t (id INTEGER PRIMARY KEY, nombre TEXT)")
sqlite.ejecutar(db, "INSERT INTO t (nombre) VALUES (@n)", {"@n": "Ana"})
sqlite.consultar(db, "SELECT * FROM t")
sqlite.ultimo_id(db)
sqlite.transaccion(db, funcion(conn) retornar "ok" fin)
sqlite.cerrar(db)
archivo.borrar("test.db")
```

> 💡 Bases de datos en memoria (:memory:):
> Puedes pasar ":memory:" como ruta para crear bases de datos temporales ultra rápidas que residen exclusivamente en la memoria RAM. Son ideales para pruebas unitarias y cachés, ya que no tocan el disco ni dejan archivos residuales al cerrarse con sqlite.cerrar().
>
> - `sqlite.conectar("blog.db")` crea un archivo físico en el directorio de trabajo. Recuerda cerrarlo con `sqlite.cerrar(db)` y borrarlo con `archivo.borrar("blog.db")` al terminar si se trata de una prueba temporal.
